1. Problem Statement¶

Most visitors to an online shop do not buy; conversion is typically reported at 1 to 3 per cent. The retailer cannot tell who is likely to purchase during a session, so every visitor receives the same treatment, wasting budget and missing the moment a customer is most receptive.

Predicting purchase likelihood mid-session enables targeted action: a discount, a live-chat prompt, or retargeting aimed at likely buyers. The data comes from session logs and clickstream tracking joined to sales records.

As a machine learning problem, one session is one row. The 17 input columns group into behavioural (page counts, time spent), engagement (BounceRates, ExitRates, PageValues) and contextual (Month, VisitorType, Region) features. The target is the Revenue column, a true/false flag for whether the session ended in a purchase. This makes the task supervised binary classification; regression does not apply because the outcome is a yes-or-no decision, not a number. The analysis is conducted on the Online Shoppers Purchasing Intention dataset (Sakar et al., 2019) from the UCI Machine Learning Repository (https://archive.ics.uci.edu/ml/machine-learning-databases/00468/online_shoppers_intention.csv). It suits this assignment: a large, clean, realistically imbalanced set with enough features for meaningful preprocessing.

2.1 Data Exploration: Discussion¶

The data set has 12,330 rows and 18 columns covering ten months: January and April are absent. Full-year seasonality therefore cannot be measured, and the Month_num feature has gaps. All 221,940 cells are populated, so no imputation was needed and no imputation artefacts enter the model. The real issue is distribution shape: Informational_Duration and PageValues are strongly right-skewed (7.58 and 6.38) and 80.5 and 77.9 per cent zero, while ProductRelated_Duration is skewed at 7.26. PageValues later proves the strongest predictor despite being zero for four sessions in five. The 125 duplicate rows were kept: identical behaviour is plausible across two genuine sessions.

15.5 per cent of sessions (1,908) ended in a purchase and 84.5 per cent (10,422) did not, a ratio of about 5.5 to 1. SMOTE is therefore applied to the training folds (Section 3.1).

A classifier answering "no purchase" every time would score that same 84.5 per cent while recording zero recall and zero F1 on buyers. F1 selects the model, with ROC-AUC as a threshold-independent secondary measure. The two error types differ commercially: 107 missed buyers against 162 wasted discounts, and without a cost per conversion neither can be weighted.

3.1 Justification of Preprocessing Decisions¶

Label encoding was applied to Month and VisitorType, imposing an artificial order with no real meaning. Tree models split on thresholds so are largely unaffected, but this is a genuine weakness for logistic regression and SVM, whose feature maxima span 0.20 (BounceRates) to 63,974 (ProductRelated_Duration), a ratio near 320,000 to 1, and are therefore scaled.

ProductsPerPage measures how product-focused a session is, ProductDurationPerPage engagement depth rather than raw dwell time, and TotalPages and TotalDuration session size. Log1p handles the skewed features because it accepts zeros. The comparison above tests whether these additions help.

An 80/20 stratified split preserves the class ratio and leaves 382 buyers in the test set, enough to keep minority-class precision and recall stable. Five folds leave 1,973 validation rows each, about 305 of them buyers, which is enough for a stable minority-class F1, and hold the Random Forest search to 60 fits rather than the 120 that ten folds would require. Permutation importance is averaged over five repeats to reduce shuffling randomness. SMOTE (Chawla et al., 2002) interpolates synthetic minority sessions, so it is placed inside the modelling pipeline and refitted within each cross-validation fold. Resampling the whole training set before cross-validation would let synthetic points from one fold appear in another, inflating the score.

4. Model Training and Hyperparameter Tuning¶

Four scikit-learn models (Pedregosa et al., 2011) were trained: logistic regression, random forest, histogram gradient boosting and an SVM with an RBF kernel. They differ fundamentally: a linear boundary, two tree ensembles, and a kernel method. Comparing these families tests whether the problem needs non-linear modelling. Cross-validated F1 selects the model; grid search tunes both ensembles.

4.1 Model Comparison¶

With SMOTE refitted within each cross-validation fold, all four models show a narrower F1 band (0.65-0.69) than the pre-fix leaky band (0.84-0.94). The best CV F1 was HistGradientBoosting (0.6935), with Random Forest (0.6916) very close behind - too small a difference to call either definitively better. Logistic Regression (0.6678 +/- 0.0159, AUC 0.9130) and SVM (0.6507 +/- 0.0147, AUC 0.9071) trail both tree models on F1, and SVM - previously the highest-AUC model at 0.9445 - is now weakest on both metrics. The tree-versus-linear gap also narrowed, from around 0.07 in the leaky results to around 0.03 here: non-linearity still helps, but less than it first appeared.

HistGradientBoosting (learning_rate 0.05, max_depth 6, max_iter 100) showed a learning-rate/depth trade-off: depth 6 helped at learning_rate 0.05 (F1 0.6915) but hurt at 0.10 (F1 0.6707), consistent with deeper trees plus faster learning causing overfitting. The best Random Forest configuration was max_depth=None, min_samples_leaf=1, n_estimators=200.

Because SMOTE is now confined to the training fold in each split, these CV scores are methodologically sound and can be compared directly with the held-out test score in Section 5.

6. Discussion, Limitations and Recommendations¶

Test performance

The final model achieved a test F1 of 0.6716, AUC of 0.9263 and accuracy of 0.89. The AUC shows strong ranking ability even where cases fall outside the F1 threshold.

CV-test alignment

The CV F1 (0.6935) and test F1 (0.6716) now agree within 0.02, since SMOTE sits in the pipeline and is refit each fold, keeping synthetic samples out of validation data. An earlier version resampled before cross-validation and reported an inflated 0.9426, a 0.29 gap from test: leakage, not performance.

Error analysis

Recall is 0.72 and precision 0.63: the confusion matrix shows 275 true positives, 107 false negatives and 162 false positives. The counts are asymmetric in cost: 107 missed buyers against 162 wasted discounts across 2,466 sessions, but the dataset records neither revenue per conversion nor discount cost, so the ratio stays unresolved.

Additional experiments

Threshold tuning gave an optimum of 0.51 (F1 0.6748), essentially the default. Scaling improved Logistic Regression (0.6351 to 0.6678, +0.033) and removed a convergence warning, confirming the Section 3.1 claim. Nine engineered features gave a near-zero gain (0.6895 to 0.6935), a valid if modest finding.

Limitations

Results come from one retailer, are observational rather than causal, rely on SMOTE synthetic samples, and the cost ratio between error types is unknown. The ten-month span noted in Section 2.1 also limits seasonal generalisability.

Recommendations and deployment

PageValues dominates at 0.48 against under 0.05 for every other feature, so the model leans on a single signal. Month_num ranks second and ExitRates third; Month_num is precisely the feature the missing months degrade, so the model relies on seasonality the data only partly covers. SHAP values are recommended for local explanations. For deployment, a real-time scoring API is suggested, with drift monitoring and scheduled retraining.
